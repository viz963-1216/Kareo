Submission Version: J-002-r3
Owner: Jerry
Last reviewed: 2026-09-23（依 staging `646ae7e` 與開啟中的 PR #16、#18、#26、#27）

用途：把 `docs/PRODUCT_SPEC.md` 原始 MVP 的每一項要求，對應到使用者能完成的行為、承接任務、前置條件、驗收方式與目前證據。

規則：

- 「有一個頁面／API／資料表」**不等於**需求完成。完成必須是使用者行為在**真實環境**可重現，並有 J-003 的驗收紀錄（`docs/INTEGRATION_ACCEPTANCE.md`）。
- Mock 模組驗收（C）只證明畫面與 contract 相容，不代表真實鏈路完成。
- 「前置條件」中的 D-xx 決策狀態見 `docs/MVP_DECISIONS.md`。PROPOSED／CHANGE-PROPOSED 不會縮減本表列出的原始要求。
- 本表只指派原始規格已有的要求，不新增產品功能。原始需求缺少承接任務時，標為 **缺口**，並寫明補到哪個任務。

狀態欄：`未完成`＝仍有必要項目未通過；`部分`＝有已合併的模組，但真實鏈路未驗收；`完成`＝真實 E2E 已通過並留證（目前沒有任何一列達到）。
