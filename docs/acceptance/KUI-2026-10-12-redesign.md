## 瀏覽器實測

本機 production artifact 透過唯讀測試 server 提供；公開資料代理實際 `kareo-tw.netlify.app` 的 GET。合成照護選項與位置僅在分頁記憶體，server 紀錄只有 HTTP method/path，沒有個案內容。故障測試只讓隔離的本機查詢回 503，恢復網路後操作「重新載入資訊」取得真實資料；沒有改正式服務或寫入假 PASS 的部署 E2E 檔案。

1. 首頁 → 告知：主入口可使用；checkbox Space 勾選 → Tab／Enter 開始。
2. 第一步設定合成案例（75–84、家人同住、協助有限、臺北大安、部分日常協助）；第二步選居家照顧與輔具；上一步保留全部第一步回答，再下一步仍保留服務選擇。切步焦點到標題。
3. 完成結果包含兩種需求及大安位置；「返回修改回答」帶回已提交回答。將居家照顧改 NO，再提交，結果只剩輔具。三家推薦均為臺北市大安區店面，舊推薦邏輯未退化。
4. 全部 UNKNOWN、不提供位置仍可完成，顯示沒有明確需求並提供補充／1966，不自動宣稱沒有長照需求。
5. 資訊頁顯示實際 `KB-2026-09-24-001`、本版發布 2026/10/03、官方來源與實際日期；API 類別 OTHER 回真實空結果，畫面能清除篩選。臨時 503 顯示故障與重試，恢復後讀回真實 21 筆資訊。
6. 手機表單：`innerWidth=scrollWidth=375`；選單高度 48px、地址輸入約 51.6px、主按鈕約 54.4px；正文 18px，h1 28px。手機首頁及平板結果页同樣無橫向溢出。
7. Chrome 顯示「縮放比例：200%」；1280px 測試 viewport 下 `innerWidth=scrollWidth=640`、DPR=2。首頁／資訊／評估內容可重排、控制項可用。測後恢復 100%。
8. 首次 Tab 顯示 skip link，焦點色 `rgb(0,95,204)`；Enter 移到 `main-content`。Space／Tab／Enter可走告知與兩步評估。完整螢幕閱讀器與全部頁面鍵盤順序仍待更廣驗證。
