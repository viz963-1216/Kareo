## 1. 原則

1. 資料最小化：只收完成「初評 → 推薦 → 媒合聯絡」所必要的資料。
2. 目的限定：資料只用於 §2 列出的用途，不做行銷、不販售、不提供給與本次媒合無關的第三方。
3. 匿名優先：評估與推薦不需要姓名電話；只有使用者主動送出媒合需求時才收聯絡資料。
4. 同意可追溯：每一筆同意都記錄版本、時間，且可撤回。
5. 期限到期即刪除或去識別化，並可由使用者主動要求刪除。

## 2. 資料清單與必要性

| 資料 | 何時收 | 用途 | 必要性 | 敏感度 | 保存期限（建議） |
|---|---|---|---|---|---|
| 匿名 session（ID、token 雜湊、建立／最後使用時間） | 進站開始評估 | 串起同一使用者的評估、推薦、媒合 | 必要 | 低 | 最後使用後 90 天刪除 |
| 同意紀錄（三種文件版本、時間、撤回時間） | 同意頁 | 證明使用者在何種告知下同意 | 必要 | 低 | 3 年（僅保留版本與時間，不含健康資料） |
| 年齡區間、縣市、行政區 | 評估 | 判斷可能需求、推薦服務範圍 | 必要（只收區間與行政區） | 中 | 同 session |
| 行動能力、日常生活協助程度、居住與照顧者狀況 | 評估 | 初步需求判斷 | 必要 | **高（健康相關）** | 同 session |
| 自由文字描述 | 評估（選填） | 補充需求 | **選填**，上限 500 字 | **高（可能含健康資訊）** | 同 session；只在 server 端做關鍵字比對，不送外部服務 |
| GPS／精確座標 | **MVP 不收集**（D-08） | — | 不必要 | 高 | — |
| 聯絡人稱呼、電話 | 使用者送出「我要媒合」 | Kareo 接件人聯繫使用者 | 送出媒合時必要 | 高 | 案件結案或取消後 180 天刪除聯絡欄位 |
| 媒合案件（服務類型、Provider、狀態、狀態歷程） | 同上 | 接件追蹤 | 必要 | 中 | 結案後 1 年（聯絡欄位依上列先刪除） |
| 系統 log | 全程 | 除錯、安全 | 必要 | 不得含個資 | 30 天 |
| IP 位址 | 限流 | 防濫用 | 必要 | 中 | **只存雜湊**，限流視窗結束即失效，不寫入業務資料表 |

不收集：身分證字號、病歷、病歷號、診斷證明、銀行資料、照片（DATA_MODEL §30）。

## 3. 同意版本

### 3.1 三份文件

| 文件 | 版本欄位 | 內容 |
|---|---|---|
| 免責聲明 | `disclaimerVersion` | 初步預估、非正式資格／等級／補助核定、非醫療診斷、請洽 1966 |
| 隱私告知 | `privacyVersion` | 本文件 §2、§4、§5、§6 的使用者版本 |
| 服務條款 | `termsVersion` | 免費服務、媒合範圍、Kareocar 為外部服務 |

### 3.2 版本規則

- 版本格式：`YYYY-MM-DD-rN`，例如 `2026-10-01-r1`；草稿加 `-draft` 後綴，例如 `2026-10-01-r1-draft`。
- 後端只接受 `contracts/legal/consent-versions.json` 中 `status = ACTIVE` 的版本組合（由 Jerry 維護；目前只有 DRAFT）。帶有 `-draft` 的版本在 production 一律拒絕。
- 文件內容變更 → 新版本。已同意舊版本的 session，在新版本 ACTIVE 後進行**新的** Assessment 或 Lead 前必須重新同意；既有資料不受影響。
- 目前前端送出的版本值必須改為讀取上述清單，不得寫死（C 後續任務）。

### 3.3 撤回同意

- 使用者可在結果頁或任何時候撤回（`POST /api/v1/consent/withdraw`，見 API_CONTRACT）。
- 撤回後：該 session 不得再建立 Assessment、Recommendation 或 Lead；已提交的 Lead 標記 `CANCELLED`（原因 `CONSENT_WITHDRAWN`）並通知接件人停止聯繫；session 資料進入刪除流程（§6）。

### 3.4 媒合聯絡同意

送出 Lead 時另外需要使用者勾選「同意 Kareo 服務人員以此電話聯繫我，並在我同意後將需求轉告服務單位」。未勾選不得建立 Lead（`contactConsent: true` 為必填，見 API_CONTRACT §12）。

## 4. 誰可以看到資料

| 角色 | 可見資料 | 方式 |
|---|---|---|
| 使用者本人 | 自己 session 的評估結果、推薦、媒合狀態 | 持有 session token（API_CONTRACT §3.1） |
| Kareo 接件人 | 被指派 Lead 的稱呼、電話、服務類型、行政區、評估摘要；**不看自由文字原文**，除非使用者在電話中同意 | 受保護內部指令（LEAD_OPERATIONS §4） |
| Jerry（資料管理者） | 維運必要範圍 | 同上，所有存取留紀錄 |
| 服務單位（Provider） | **不自動取得**；接件人在使用者口頭同意後才轉告必要資訊 | 人工 |

## 5. 外部資料流（D-01 方案 B）

**MVP 不使用任何外部 AI 服務。** 評估回答與自由文字只在 Kareo 自己的 Netlify Functions 與 Supabase 內處理，不傳送給第三方。

資料只會存在以下服務（皆由 Kareo 管理）：

|---|---|---|
| Netlify | 網站與 API 執行 | （待填） |
| Supabase | 資料庫 | （待填，依專案建立時選的 region） |

未來若引入 AI，需先修訂本節、新增同意版本，並重新取得同意。

## 6. 刪除

### 6.1 使用者自助刪除

- `DELETE /api/v1/session`（需 session token）：立即使 token 失效，並將 session 標記待刪除。
- 7 天內由清理作業實際刪除該 session 的 Assessment、CareNeedProfile、RecommendationRun／Item；Lead 的聯絡欄位立即清空，Lead 狀態改為 `CANCELLED`（原因 `USER_DELETED`），案件骨架（無個資）保留供統計。
- 同意紀錄保留版本與時間（不含健康資料），以證明曾經取得同意。

### 6.2 客服管道刪除

- 使用者無法使用 token 時（例如換裝置），可透過客服信箱要求刪除，需提供 Lead 編號或聯絡電話以供比對。
- **客服信箱：待 Jerry 指定**（`BLOCKED`；未指定前 J-004 不開放正式媒合）。
- 回覆時限（建議）：7 個工作天內完成並回覆。

### 6.3 到期清理作業（B-011 實作，J-004 驗收排程）

- 每日執行一次，支援 `--dry-run`，輸出將刪除筆數與類型（不輸出個資）。
- 需授權角色執行；失敗可重試且冪等；每次執行留紀錄（時間、筆數、結果）。
- 實體刪除，不只是隱藏。資料庫備份依 J-004 備份保存期限自然汰換，並在隱私告知中說明。

## 7. 安全要求摘要（完整規格見 ARCHITECTURE §20）

- 所有 API 走 HTTPS；資料表 RLS 開啟、anon／authenticated 無權限。
- log 與錯誤訊息不得含健康原文、姓名、電話、token、secret。
- 前端不得持有任何 service key 或 AI key。
- session token 以雜湊儲存，不以明文寫入資料庫或 log。

**免責聲明（disclaimer）**

Kareo 提供的是依您填寫資料所做的**初步預估**與資訊整理，不是政府正式的長照資格、長照需要等級（CMS）或補助核定，也不是醫療診斷。實際資格、等級、服務內容與補助，請以長照專線 **1966** 或所在地長期照顧管理中心的正式評估為準。

**隱私告知（privacy，重點版）**

- 評估不需要提供姓名或電話。
- 您的評估回答（包含行動能力、日常生活協助等與健康相關的資訊）只會由 Kareo 系統依固定規則產生初步結果，不會提供給其他公司或 AI 服務。
- 只有在您按下「我要媒合」並勾選同意後，我們才會保存您的稱呼與電話，由 Kareo 服務人員聯繫您。未經您同意，不會把您的資料交給服務單位。
- 評估資料在最後使用後 90 天刪除；媒合聯絡資料在案件結束後 180 天刪除。您可以隨時在結果頁刪除資料或撤回同意，也可以來信（客服信箱待公布）要求刪除。

**媒合聯絡同意（Lead 表單）**

☐ 我同意 Kareo 服務人員以上述電話聯繫我，並在我同意後將需求轉告服務單位。
