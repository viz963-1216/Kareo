## 1. 原則

1. 資料最小化：只收完成「初評 → 推薦 → 媒合聯絡」所必要的資料。
2. 目的限定：資料只用於 §2 列出的用途，不做行銷、不販售、不提供給與本次媒合無關的第三方。
3. 匿名優先：評估與推薦不需要姓名電話；只有使用者主動送出媒合需求時才收聯絡資料。
4. 同意可追溯：每一筆同意都記錄版本、時間，且可撤回。
5. 期限到期即刪除或去識別化，並可由使用者主動要求刪除。

## 3. 同意版本

### 3.1 三份文件

| 文件 | 版本欄位 | 內容 |
|---|---|---|
| 免責聲明 | `disclaimerVersion` | 初步預估、非正式資格／等級／補助核定、非醫療診斷、請洽 1966 |
| 隱私告知 | `privacyVersion` | 本文件 §2、§4、§5、§6 的使用者版本 |
| 服務條款 | `termsVersion` | 免費服務、媒合範圍、Kareocar 為外部服務 |

### 3.2 版本規則

- 版本格式：`YYYY-MM-DD-rN`，例如 `2026-10-01-r1`；草稿加 `-draft` 後綴，例如 `2026-10-01-r1-draft`。
- 後端只接受 `contracts/legal/consent-versions.json` 中 `status = ACTIVE` 的版本組合（由 Jerry 維護；目前只有 DRAFT）。帶有 `-draft` 的版本在 production 一律拒絕。
- 文件內容變更 → 新版本。已同意舊版本的 session，在新版本 ACTIVE 後進行**新的** Assessment 或 Lead 前必須重新同意；既有資料不受影響。
- 目前前端送出的版本值必須改為讀取上述清單，不得寫死（C 後續任務）。

### 3.3 撤回同意

- 使用者可在結果頁或任何時候撤回（`POST /api/v1/consent/withdraw`，見 API_CONTRACT）。
- 撤回後：該 session 不得再建立 Assessment、Recommendation 或 Lead；已提交的 Lead 標記 `CANCELLED`（原因 `CONSENT_WITHDRAWN`）並通知接件人停止聯繫；session 資料進入刪除流程（§6）。

### 3.4 媒合聯絡同意

送出 Lead 時另外需要使用者勾選「同意 Kareo 服務人員以此電話聯繫我，並在我同意後將需求轉告服務單位」。未勾選不得建立 Lead（`contactConsent: true` 為必填，見 API_CONTRACT §12）。

## 6. 刪除

### 6.1 使用者自助刪除

- `DELETE /api/v1/session`（需 session token）：立即使 token 失效，並將 session 標記待刪除。
- 7 天內由清理作業實際刪除該 session 的 Assessment、CareNeedProfile、RecommendationRun／Item；Lead 的聯絡欄位立即清空，Lead 狀態改為 `CANCELLED`（原因 `USER_DELETED`），案件骨架（無個資）保留供統計。
- 同意紀錄保留版本與時間（不含健康資料），以證明曾經取得同意。

### 6.2 客服管道刪除

- 使用者無法使用 token 時（例如換裝置），可透過客服信箱要求刪除，需提供 Lead 編號或聯絡電話以供比對。
- **客服／刪除請求信箱：[viz963@gmail.com](mailto:viz963@gmail.com)**（Jerry 2026-10-03 指定）。信箱已指定不代表收件演練、處理人與正式隱私核准已完成。
- 回覆時限（建議）：7 個工作天內完成並回覆。

### 6.3 到期清理作業（B-011 實作，J-004 驗收排程）

- 每日執行一次，支援 `--dry-run`，輸出將刪除筆數與類型（不輸出個資）。
- 需授權角色執行；失敗可重試且冪等；每次執行留紀錄（時間、筆數、結果）。
- 實體刪除，不只是隱藏。資料庫備份依 J-004 備份保存期限自然汰換，並在隱私告知中說明。

## 7. 安全要求摘要（完整規格見 ARCHITECTURE §20）

- 所有 API 走 HTTPS；資料表 RLS 開啟、anon／authenticated 無權限。
- log 與錯誤訊息不得含健康原文、姓名、電話、token、secret。
- 前端不得持有任何 service key 或 AI key。
- session token 以雜湊儲存，不以明文寫入資料庫或 log。
